# P02 상태 구현 확인과 최소 수정

권한 모드: 요청 1은 Plan, 요청 2는 Manual
사용법: '## 요청' 아래 줄을 Claude Code 입력창에 그대로 붙여 넣는다. 또는 이 파일을 내 서버 프로젝트의 prompts\ch08\ 에 복사하고 입력창에 `@prompts/ch08/P02_state_check.md 의 요청을 수행해 줘`라고 입력한다.
경로가 다른 자기 프로젝트는 요청의 @경로를 실제 파일 경로로 바꾼 뒤 쓴다. 다른 프로젝트나 배포 원본을 덮어쓰지 않는다.

## 요청 1 (Plan 모드에서 보낸다)
@docs/state-rules.md @docs/api-spec.yaml 와
반환 처리 소스를 읽어 줘. 지금은 파일을 수정하지 마.
등록자만 반환하는지, 반복 반환이 200·RETURNED를
유지하는지, 반환 뒤 PUT이 상태와 등록자를 유지하는지
코드와 테스트로 대조해 줘.
다른 곳이 있으면 고칠 파일과 줄,
실행할 테스트 이름을 제안해 줘.

요청 1의 답을 읽고 고칠 항목을 고른 뒤 모드를 Manual로 바꾼다.

## 요청 2 (Manual 모드)
P01 권한표 또는 P02 상태 점검에서 내가 고른
[표의 행·수정 항목] 하나만 고쳐 줘(괄호는 내가 채운다).
원인 파일과 관련 테스트만 바꾸고, 기존 검사를 지우거나
기대값을 실제 결과에 맞춰 바꾸지 마.
.\gradlew.bat test 를 실행해
종료 코드와 실패한 테스트 이름을 보여 줘.
결과는 reports/verification.md의
'## 8장 Postman·Newman 검사' 절에
'8장 P02 권한·상태 구현' 항목으로 덧붙여 줘(절이 없으면 만든다).

읽는 파일: docs/state-rules.md, docs/api-spec.yaml, 반환 처리 src와 테스트

주로 바뀔 파일(예시): 요청 2에서 고른 원인 파일(인증 필터·보안 설정·Service 등)과 관련 테스트, reports/verification.md
목록 밖의 파일을 만들거나 바꿔야 하면 Claude Code가 먼저 이유를 말해야 한다. 파일 이름은 AI마다 다를 수 있으며, 명세·권한·실제 실행 결과가 기준이다.

확인과 기록: BUILD SUCCESSFUL과 실패 0이면 성공이다. 실패하면 실패한 테스트 이름을 읽고 원인을 다시 묻는다.

# 입력 요구사항: 교내 분실물 센터

5장에서 정리한 화면을 실제 서버에 연결할 준비를 한다. 학생이 사용할 화면은 S01 목록, S02 상세,
S03 물건 등록, S04 로그인 네 개다. 화면 버튼의 위치를 API가 구현하는 것은 아니다.
API가 어떤 입력을 받고 무엇을 응답해야 하는지 먼저 설계한다.

## 기능 요구

5장 요구사항표(R01~)를 이 절에 옮겨 적는다. 아래 표는 제공 예다. 내 5장 표가 있으면 그 내용으로 바꾼다.

| 번호 | 사용자 행동 | 조건 | 화면 | 확인할 결과 |
| --- | --- | --- | --- | --- |
| R01 | 목록 보기 | 로그인 없이 | S01 | 이름·발견 장소·상태를 확인한다. |
| R02 | 상세 보기 | 목록에서 선택 | S02 | 선택한 물건의 상세가 열린다. |
| R03 | 물건 등록 | 로그인 후 | S03 | 입력 확인과 완료 안내 뒤 목록으로 간다. |
| R04 | 로그인 | 등록 진입 중 | S04 | 로그인 완료 후 등록으로 돌아간다. |
| R05 | 반환 표시 | 등록한 학생 | S02 | 반환 완료 상태를 구분해 표시한다. |

- 로그인하지 않아도 물건 목록과 상세를 볼 수 있다.
- 로그인한 사용자는 물건을 등록한다. 서버가 로그인한 사람을 등록자로 정한다.
- 등록한 사용자만 자기 물건의 설명 수정·반환 표시·삭제를 할 수 있다.
- owner_id는 등록한 사용자 ID다. 실제 물건을 잃어버린 주인의 ID를 뜻하지 않는다.
- title은 물건 이름, location은 발견 장소다. 두 값은 앞뒤 공백을 제거한 뒤 1~80자다.
- note는 특징 메모이며 선택, 최대 150자다. 빈 값은 null로 정리한다.
- 상태는 FOUND(보관 중), RETURNED(반환 완료) 두 가지다. 등록할 때 서버가 FOUND로 정한다.
- 같은 반환을 다시 요청해도 200이고 다른 필드는 그대로다. 반환 뒤 설명 수정도 200으로 허용한다.
- 회원가입에는 username(소문자 영문·숫자·밑줄 4~24자)과 password(8자 이상·UTF-8 72바이트 이하)를 받는다.
  username은 유일해야 하고 비밀번호는 BCrypt 해시로 저장한다. 비밀번호·해시는 응답하지 않는다.

## 수업에서 맞출 기술 조건

- JDK 21, Spring Boot 4.1.1, Gradle(Groovy DSL, 제공 Wrapper), Spring Data JPA, H2 2.4.240, JJWT 0.13.0을 사용한다.
- IDE는 기존 프로젝트를 연다. 최초 실행은 이미 있는 / 와 /api/health만 제공한다.
- 서버는 127.0.0.1:8097이다. JWT는 HS256, 발급자 skilltransfer-ch07, 유효시간 1800초를 기준으로 설계한다.
- 키는 최소 32바이트 난수이며 재시작 때 같은 키를 다시 쓸 방법과 Git·배포물에서 뺄 방법을 적는다.
- H2는 파일 DB ./data/chapter07을 사용한다. DB·키·파일의 보존과 초기화 방법을 구분한다.
- H2 콘솔은 dev 프로필에서만 연다. Spring Boot 4에서는 spring-boot-h2console 의존성,
  application-dev.properties의 spring.h2.console.enabled=true, 보안 설정의 /h2-console/** 허용이 모두 필요하다.
- API 경로는 /api/items, /api/items/{id}, /api/items/{id}/return, /api/auth/signup, /api/auth/login으로 맞춘다.
- API 문서에는 공개/인증/등록자 권한, 요청·응답 JSON, 정상·실패 상태, 필드 결정 주체를 작성한다.
- 조회 200, 등록 201과 Location, 삭제 204와 빈 본문, 입력 오류 400, 인증 401, 다른 등록자 403,
  없는 번호 404, 중복 username 409를 구분한다.
- 오류 응답은 {code, message, errors} 형식으로 통일한다. errors에는 입력 항목별 안내 문구(S03 문구)를 담는다.
  스택 추적·SQL·토큰은 응답에 넣지 않는다.
- 입력 JSON에 owner_id·status처럼 정하지 않은 항목이 있으면 400으로 거절한다. 화면에 owner_id나 status를 입력받는 칸을 추가하지 않는다.
- 공개 GET은 토큰 없이 보낸다. Authorization 헤더를 붙였는데 토큰이 무효·만료이면 401로 거절한다.

## 표본 자료(시드)

- 표본 계정: student01(id 101), student02(id 102). 비밀번호 study-1234는 이 로컬 실습에서만 쓰는 공개 표본 값이다.
- 표본 물건 7: 파란 우산 · 도서관 · 메모 null · FOUND · owner_id 101
- 표본 물건 8: 검정 물병 · 체육관 · 메모 '스티커 있음' · FOUND · owner_id 102
- 사용자 표가 비어 있을 때만 한 번 넣는다. 재시작할 때 중복으로 넣지 않는다.
- 비밀번호는 BCrypt 해시로 저장한다. 평문을 DB나 SQL 파일에 두지 않는다.
- 새 번호가 표본과 겹치지 않도록 ID는 SEQUENCE로 만들고 시작값을 물건 9, 사용자 103으로 정한다.
- 새 등록 예: 노란 필통 · 미술실. 새 id는 서버 응답을 읽고 고정하지 않는다.
- 8장 Postman, 10장 앱 연결, 11장 통합 검사가 이 표본을 전제로 한다.

## 범위

이메일 인증·비밀번호 찾기·소셜 로그인·인터넷 배포를 추가하지 않는다.
사진 첨부는 기본 S03에 없다. P08에서만 선택 확장으로 설계하고 검증한다.
상세 화면의 버튼 숨김은 편의 기능이고 서버의 등록자 검사를 대신하지 않는다.

# 입력 요구사항: ICN Subway Steps

문서 정보: 2026-10-20 · 교재 7장 requirements.md(분실물 예)를 내 앱 기준으로 바꿈 · 작성 Claude Code, 검토: (본인 이름)

외국인 여행객이 인천공항 T1 입국장에서 서울역행 공항철도(AREX) 열차에 탈 때까지 단계별 사진 카드로 안내하는 앱의 서버다.
앱 화면은 S01 경로 목록, S02 단계 안내, S03 팁 등록, S04 로그인, S05 설정, S06 내 팁이다(시안 v03).
화면 버튼의 위치를 API가 구현하는 것은 아니다. API가 어떤 입력을 받고 무엇을 응답하는지 정한다.
서버 계약의 기준은 docs/api-spec.yaml, 테이블과 시드는 docs/data-model.md다.

## 기능 요구

5장 docs/ui-requirements.csv(R01~R06)와 시안 v03에서 추가된 S06(R08)을 옮겼다. R07 설정(테마·언어·로그아웃)은 앱 안에서만 처리하므로 서버 요구가 없다.

| R08 | 내 팁 보기 | 로그인 후 · 하단 메뉴 '내 팁' | S06 | 내가 올린 팁과 그 단계, 상태 변경. 로그인 전이면 로그인 안내. | GET /api/me/tips |

- 로그인하지 않아도 경로·단계·팁을 볼 수 있다(온라인 전용 결정: 경로·단계도 서버에서 받는다).
- 로그인한 사용자는 단계마다 팁을 올린다. 서버가 로그인한 사람을 올린 사람(owner_id)으로 정한다.
- 올린 사용자만 자기 팁의 상태를 VERIFIED(작성자 확인)·OUTDATED(정보 오래됨)로 바꾼다. 다른 사용자의 '오래됨' 신고는 범위 밖.
- 등록할 때 서버가 status=VERIFIED, verified_at=지금으로 정한다. 상태를 바꿀 때마다 verified_at을 지금으로 갱신한다(작성자 확인 + 날짜 결정).
- title은 팁 제목, location은 정확한 위치다. 두 값은 앞뒤 공백을 제거한 뒤 1~80자다. 글자 수는 유니코드 코드 포인트로 센다(이모지 1개 = 1자).
- note는 메모이며 선택, 앞뒤 공백 제거 뒤 최대 150자. 빈 값은 null로 정리한다.
- route·step_no는 S02에서 넘어온 값이다. 안내 중인 경로(EXPRESS·LOCAL)와 그 경로의 1~단계 수만 받는다.
- 회원가입에는 username(소문자 영문·숫자·밑줄 4~24자)과 password(8자 이상·UTF-8 72바이트 이하)를 받는다.
  username은 유일해야 하고 비밀번호는 BCrypt 해시로 저장한다. 비밀번호·해시는 응답하지 않는다.
  (앱 화면에는 회원가입이 없다. 계정을 어떻게 얻을지는 5장 검증 결정의 '아직 결정할 것'으로 남아 있다.)
- 엘리베이터 정보는 현장 확인 뒤 추가한다. 그 전까지 단계 응답의 elevator는 null이며 앱은 '확인 중'으로 표시한다.
- 안내 종료점은 공항철도 탑승까지다. 단계 데이터는 승강장 탑승 단계에서 끝난다.

## 수업에서 맞출 기술 조건

- JDK 21, Spring Boot 4.1.1, Gradle(Groovy DSL, 제공 Wrapper), Spring Data JPA, H2 2.4.240, JJWT 0.13.0을 사용한다.
- 서버는 127.0.0.1:8097이다. JWT는 HS256, 발급자 skilltransfer-ch07, 유효시간 1800초다.
- 키는 최소 32바이트 난수이며 재시작 때 같은 키를 다시 쓴다(data/.jwt-secret 파일 또는 환경 변수 JWT_SECRET). Git·배포물에서 뺀다.
- H2는 파일 DB ./data/icn-subway를 사용한다. DB·키의 보존과 초기화 방법은 docs/data-model.md에 적는다.
- H2 콘솔은 dev 프로필에서만 연다. spring-boot-h2console 의존성, application-dev.properties의
  spring.h2.console.enabled=true, 보안 설정의 /h2-console/** 허용이 모두 필요하다.
- API 경로: /api/routes, /api/routes/{route}/steps, /api/tips, /api/tips/{id}, /api/tips/{id}/status, /api/me/tips,
  /api/auth/signup, /api/auth/login.
- API 문서에는 공개/인증/올린 사람 권한, 요청·응답 JSON, 정상·실패 상태, 필드 결정 주체를 작성한다.
- 조회 200, 등록 201과 Location, 입력 오류 400, 인증 401, 다른 사용자 403, 없는 번호 404, 중복 username 409를 구분한다.
  (팁 삭제는 화면에 없어 만들지 않는다. 따라서 204 응답은 없다.)
- 오류 응답은 {code, message, errors} 형식으로 통일한다. errors에는 입력 항목별 안내 문구(S03 문구)를 담는다.
  스택 추적·SQL·토큰은 응답에 넣지 않는다.
- 입력 JSON에 status·ownerId·verifiedAt처럼 정하지 않은 항목이 있으면 400으로 거절한다.
- 공개 GET은 토큰 없이 보낸다. Authorization 헤더를 붙였는데 토큰이 무효·만료이면 401로 거절한다.

## 표본 자료(시드)

- 표본 계정: student01(id 101), student02(id 102). 비밀번호 study-1234는 이 로컬 실습에서만 쓰는 공개 표본 값이다. BCrypt 해시로 저장한다.
- 경로 3개(EXPRESS·LOCAL 각 5단계, T2 준비 중)와 단계 10개: 시안 v03의 ROUTES 문구. 현장 확인 전 초안이다.
- 표본 팁 7: 직통 3단계 · 예시 팁(example=true) · student02 · VERIFIED
- 표본 팁 8: 일반 4단계 · student01 · OUTDATED · 메모 있음
- 표가 비어 있을 때만 한 번 넣는다. 재시작할 때 중복으로 넣지 않는다.
- ID는 SEQUENCE로 만들고 시작값을 팁 9, 사용자 103으로 정한다. 새 id는 서버 응답을 읽고 고정하지 않는다.

## 범위

이메일 인증·비밀번호 찾기·소셜 로그인·인터넷 배포를 추가하지 않는다.
팁 사진 첨부는 시안에서도 숨겼다(미정). 필요하면 P08 선택 확장으로 따로 설계한다.
팁 수정·삭제, 다른 사용자의 신고, 실시간 열차 시간표·요금·지도는 만들지 않는다.
화면의 상태 변경 버튼 숨김은 편의 기능이고 서버의 올린 사람 검사를 대신하지 않는다.

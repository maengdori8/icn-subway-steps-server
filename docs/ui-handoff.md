## 확정한 것

네 화면은 목록·상세·물건 등록·로그인이다. 목록과 상세는 로그인 없이 보며, 로그인 후 하던 화면(등록이면 S03, 반환이면 S02)으로 돌아온다. 등록은 물건 이름과 발견 장소가 필수이며 앞뒤 공백을 지운 뒤 1~80자, 메모는 선택이며 최대 150자다. 실패한 경우 다른 입력값을 유지한다. 등록 중 중복 누름을 막고 성공을 확인한 뒤 완료 안내와 함께 목록으로 간다. 등록과 로그인의 취소는 목록으로 간다.

기본 녹색 시안의 주요 색은 #285E46, 바탕은 #FDFEF9, 본문은 #203D34, 입력칸 테두리는 #7A8C78이다. 웹 시안의 작은 글자는 Flutter 참고앱에서 body16·label14·caption12로 키우고 최소 누르는 영역48을 적용한다. 이 조정은 원래 웹 CSS와 구분해 design-system.json의 flutterAdaptations에 기록했다.

## 아직 결정할 것

- 작성 중 취소할 때 확인창을 띄울지, 임시 입력을 다시 열 때 복원할지는 미정이다. 강사가 보여 주는 작동 모형은 결정을 대신하지 않도록 확인 없이 목록으로 가고 내용을 복원하지 않는다. 이것은 결정이 아니라 모형의 단순화다.
- 시안과 API의 필수값·오류 규칙이 다르면 임의로 API를 바꾸지 않고 차이를 질문한다.

## 화면 항목과 데이터 이름(7장 데이터 모델의 입력)

화면에 보이는 항목을 4장 테이블 초안과 같은 이름 후보로 연결합니다. 실제 이름·길이는 7장에서 docs/data-model.md로 확정합니다.

| 화면 항목 | 데이터 이름 후보 | 규칙 |
| --- | --- | --- |
| 물건 번호 | id | 목록에서 상세로 넘기는 값. 사용자가 입력하지 않음 |
| 물건 이름 | title | 필수, 앞뒤 공백 제거 후 1~80자 |
| 발견 장소 | location | 필수, 앞뒤 공백 제거 후 1~80자 |
| 메모 | note | 선택, 최대 150자 |
| 상태(보관 중 / 반환 완료) | status (FOUND / RETURNED) | 등록할 때는 보관 중. 등록한 사용자만 반환 완료로 바꿈 |
| 등록자 | owner_id | 로그인한 사용자. 화면에서 입력받지 않음 |

## 화면별 API 요구 목록

화면이 서버에 요청해야 하는 일을 정리한 표입니다. 요청 경로는 후보이며, 7장 P01에서 docs/api-spec.yaml로 확정합니다. 확정한 계약이 이 표와 다르면 그 이유를 이 문서에 덧붙입니다.

| 화면ID | 사용자 행동 | 필요한 요청 후보 | 보내는 값 | 받는 값 | 로그인 필요 | 실패 시 화면 상태 |
| --- | --- | --- | --- | --- | --- | --- |
| S01 | 목록 보기 | GET /api/items | 없음 | 물건 목록(번호·이름·발견 장소·상태) | 아니요 | 불러오는 중 → 0건이면 빈 목록, 읽지 못하면 읽기 실패와 다시 시도 |
| S02 | 상세 보기 | GET /api/items/{id} | 물건 번호 | 이름·발견 장소·메모·상태·등록자 | 아니요 | 없는 번호면 찾을 수 없다는 안내 뒤 목록, 읽지 못하면 다시 시도 |
| S02 | 반환 완료로 변경 | PATCH /api/items/{id}/return | 물건 번호(본문 없음) | 바뀐 물건 정보 | 예(등록자만) | 로그인 전이면 S04 → S02 복귀, 다른 등록자면 거부 안내, 처리 실패면 상태 유지와 다시 시도 |
| S03 | 등록하기 | POST /api/items | 물건 이름·발견 장소·메모(등록자·상태는 보내지 않음) | 새 물건 번호 | 예 | 입력 오류면 칸 아래 문구와 값 유지, 처리 실패면 값 유지와 다시 시도, 로그인이 끝났으면 S04 |
| S04 | 로그인 | POST /api/auth/login | 사용자 이름·비밀번호 | 로그인 확인 값·사용자 이름 | 해당 없음 | S04에 머물며 입력 확인 안내 |
